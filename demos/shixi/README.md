# 五帝世系 · 血缘与继位

《祖先》第一卷的人物关系图。二十二个人物、三十五条边，图上二十个节点——配偶写在伴侣框内，不单独占位。画的是「谁是谁的儿子」与「谁接了谁的位」这两件事，以及这两件事对不上的地方。

## 这个演示在做什么

第一卷讲的是符号，不是王朝。女娲是蛙，伏羲是蛇，炎帝是牛，黄帝是龙——这些都不是人，是文化代码。但《史记·五帝本纪》把他们排成了一条世系。这条世系就是本的图的对象。

图上有三种线：

- **实线**：亲子。只连父系，母系不单独画（见下）。
- **虚线箭头**：继位。兄终弟及、父死子继、孙继祖位、禅让，全走这一条。
- **红线**：敌对与杀。阪泉、涿鹿。

三种线放在一起，问题就出来了：尧在第四代，舜在第八代，禹又回到第四代。继位顺序是 4 → 8 → 4，与血缘的深浅完全错开。这不是画错了，是《史记》原文如此；本书认为这正是后世追述拼接的痕迹。

## 布局规则

1. **代数**：从根出发沿父系的最长路径。无父者为第 0 代，子代为父代 +1。
2. **横向**：每一支按子树宽度占位，父辈落在长子与幼子的中点。所以单传的链条是垂直的一条线（颛顼→穷蝉→敬康→句望→桥牛→瞽叟→舜）。
3. **配偶**：写在人物框内第二行，不单独占位。嫘祖、昌仆因此没有独立节点，她们的资料在点击配偶人物时可见。
4. **母系边不画线**：昌仆 → 颛顼这条边在数据里存在，图上不单独成线。夫妻并列、子代挂在父系下方，是族谱图的通行画法；把母系边也画出来，八代之后就是一团乱麻。

## 演化进程

右栏的七个步骤是「继位链」，不是年表。每一步停在一个接过权位的人身上，旁白说明他与上一位的关系。从黄帝到禹：

| 步  | 人   | 代  | 与上一位的关系         |
| --- | ---- | --- | ---------------------- |
| 1   | 黄帝 | 0   | —                      |
| 2   | 颛顼 | 2   | 孙继祖位               |
| 3   | 帝喾 | 3   | 族孙继位，换回玄嚣一系 |
| 4   | 挚   | 4   | 父死子继               |
| 5   | 尧   | 4   | 兄终弟及               |
| 6   | 舜   | 8   | 与尧差四代             |
| 7   | 禹   | 4   | 与舜差四代，方向相反   |

## 数据在哪

人物与关系不在本目录，在 `corpus/`：

- `corpus/people/shanggu.js`：二十一个人物，含别名、身份、按语。
- `corpus/relations/shanggu.js`：三十五条边，每条带 `src` 与 `source`。

本目录的 `data.js` 只有三样东西：`META`（含 `view: 'kin'`）、`STEPS`（演化进程的旁白）。

## 证据

全部为 `src: 'legend'`。理由不是"不可信"，而是"这是被写下来的谱系，不是挖出来的实物"。出处以《史记》五帝、夏、殷、周四个本纪为主。

异说与取舍：

- **炎黄同出少典**。《国语·晋语》有此说，本书不取。图上炎帝与黄帝之间只有敌对边，没有血缘边。
- **尧舜的辈分**。《史记》明言舜为颛顼七世孙，与尧相差四代。这个矛盾原文就有，不是绘图造成的。
- **帝喾诸子的母系**。挚与尧异母、契与弃异母，均按《史记》所记写入，兄弟边只在这些地方显式存在。
- **生卒年一律留空**。传统纪年（如黄帝前 2698—前 2599）是后世推算，不写进数据。

## 想改点什么

改人物与关系只碰 `corpus/`，改布局只碰 `app.js`。改完运行：

```bash
node scripts/check.mjs
```

它会检查关系两端是否存在、`kind` 与 `role` 是否在词表内、亲子关系是否成环、`STEPS` 是否指向真实人物。
