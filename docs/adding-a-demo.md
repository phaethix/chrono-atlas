# 新增一个演示

一个演示就是 `demos/` 下的一个目录，加上根目录画廊里的一张卡片。没有注册表，没有配置文件，没有构建步骤。

## 五分钟版本

```bash
git clone https://github.com/phaethix/chrono-atlas.git
cd chrono-atlas
cp -r demos/chunqiu-zhanguo demos/my-era
```

然后把 `demos/my-era/` 里的四个文件按新题材改写：

- `data.js`：换成你的势力、区域、年表
- `index.html`：改标题与描述
- `style.css`：可以沿用，也可以完全重写
- `README.md`：写清这个演示的史料依据与简化

再把 `META.id` 改成 `my-era`，与目录名一致。

最后在根目录 `index.html` 里加一张卡片：

```html
<a class="card" href="demos/my-era/index.html">
  <h3>你的题材<span>副标题</span></h3>
  <div class="meta">起止年 · 地域</div>
  <p>一句话说明这个演示看什么。</p>
  <div class="tags"><b>标签</b></div>
  <div class="go">进入演示 →</div>
</a>
```

运行校验：

```bash
node scripts/check.mjs
```

## 从零开始，而不是复制

复制最快，但春秋战国的渲染逻辑是为「多边形疆域 + 逐年归属」这一种表达写的。如果新题材的形态不同，比如想画人口曲线、军队行军路线、贸易网络，直接改 `app.js` 会比套用更省事。

这种情况下，`index.html` 里只要引入 `data.js` 和 `app.js` 两个脚本，`app.js` 从 `data.js` 读取数据即可。渲染层怎么写完全自由，校验脚本只关心 `data.js` 的结构是否自洽，不检查 `app.js` 怎么画。

## 数据从哪来

三个来源，按可靠性排序。

一是通行史书与工具书。年份和归属以《史记》《资治通鉴》这类编年记载为骨，边界以谭其骧《中国历史地图集》这类历史地图集为参考。

二是学术出版物中的历史地图。区域边界的走向通常能在此找到依据，但要注意不同著作的断代与取径可能不同。

三是公开的地理与行政区划数据。适合用作底图骨架，但历史上的边界与今天的行政区划并不对应，直接套用会产生时代错置。

无论用哪一种，在 `README.md` 里写清依据。这不是学术审查，而是让后来者知道某条边界为什么画在那里。

## 边界怎么画

顶点是 `[经度, 纬度]`，用任意工具取得即可，比如在地图上取点后抄下来。有几个实用规则。

相邻区域共用顶点。这样拼接时不会出现缝隙。做法是先定一组关键点，让相邻区域都引用同一对坐标。

不要用真实海岸线的高精度数据。这个演示的分辨率是示意图级别，几千个顶点既拖慢渲染，也超出史料能支撑的精度。

顶点顺序统一。全部顺时针或全部逆时针，混用会让描边在某些浏览器里出现缺口。

先画大区，再切小区。中原那几个小国如果先画，很容易和大区对不齐。

## 年份怎么写

公元前用负数，公元后用正数，直接写整数，不要用字符串。

```js
{ y: -260, ... }   // 公元前 260 年
{ y: 618,  ... }   // 公元 618 年
```

跨公元前后的演示，`from` 为负、`to` 为正，逻辑上不需要特殊处理。

## 表达「一国被瓜分」

一条事件的 `ch` 可以同时改多个区域：

```js
{ y: -284, t: 'merge', s: '五国合纵伐齐，宋地为魏、楚所分。',
  ch: { song: 'wei', cao: 'wei', xuzhou: 'chu' } }
```

灭国判定看的是「这个势力在变更后是否还有区域」。如果它把地盘分给了三个国家，仍然算灭亡，档案卡片会列出所有接收方。

## 常见错误

`META.id` 与目录名不一致。校验脚本会直接报错，因为画廊与链接依赖这个一致的约定。

`INIT` 漏了区域。哪怕那个区域无主，也要显式写 `none`。

年份倒序。年表须按 `y` 递增，否则状态推导会得到错误结果。写的时候同一年的事可以并列，但不要回退。

在 `app.js` 里写死起止年份。应当读 `META.from` 与 `META.to`，否则改区间时容易漏改。

区域键拼错。`ch` 里写了一个不存在的键，校验脚本会报错，但要注意它只检查键是否存在，不检查这个变更是否符合史实。史实由你负责。

## 提 PR 前

```bash
node scripts/check.mjs
```

通过之后再提。PR 模板里会让你勾选几项，包括数据来源、是否有已知简化。这几项不是形式，读者需要知道这个演示的边界在哪。
