# 数据格式

每个演示的 `data.js` 是一个普通脚本，用顶层 `const` 声明以下绑定。浏览器里直接 `<script src="data.js">` 加载即可，不需要模块系统。

校验脚本 `scripts/check.mjs` 会读取这些绑定并检查一致性，字段定义以此文为准。

## META

演示的元信息。`id` 必须与目录名一致，画廊与校验脚本都依赖这一点。

```js
const META = {
  id: 'chunqiu-zhanguo', // 目录名，必填
  title: '春秋战国', // 必填
  subtitle: '疆域与兼并', // 选填
  scope: '中国 · 黄河与长江流域', // 选填，说明地理范围
  from: -770, // 必填，起始年，公元前为负数
  to: -221, // 必填，结束年
  summary: '一句话说明这个演示看什么。', // 必填
  tags: ['中国', '先秦'], // 选填
  sources: ['《史记》'], // 选填，史料依据
  rate: 3.4, // 选填，播放时每秒推进的年数
  ticks: [{ y: -770, t: '前770' }], // 选填，时间轴刻度
  terms: { list: '势力版图' }, // 选填，界面用语
};
```

年份统一用带符号整数：公元前 770 年写 `-770`，公元 618 年写 `618`。跨公元前后时 `from` 为负、`to` 为正即可，不需要特殊处理。

### view

视图类型，缺省 `map`。

| 值    | 形态             | data.js 需要                                      |
| ----- | ---------------- | ------------------------------------------------- |
| `map` | 区域多边形与归属 | `from` `to` `S` `REGIONS` `INIT` `EVENTS` `ERAS`  |
| `kin` | 人物关系图       | 只需 `META` 与 `STEPS`，人物与关系从 `corpus/` 取 |

二十四卷里不是每卷都有地图：《五帝世系》画的是人与人的关系，《百家争鸣》以后多半要靠师承网络。校验脚本按这个字段决定跑哪一套检查，不要给关系视图硬凑一份 `REGIONS`。

### rate

`rate` 是 1× 速度下每秒推进的年数，缺省 3.4。它与 `META` 的跨度应当匹配：550 年的演示按 3.4 走完约 160 秒，7000 年的演示若仍用 3.4，一趟要半小时。

写不写都可以，但跨度大的题材应当写。这个值只影响播放，不影响拖拽与跳转。

### ticks

时间轴下方那排年份标签。缺省由 `app.js` 按跨度自动取整（一万、五千、两千、一千、五百……），跨度过大或过小时最好显式给出。

```js
ticks: [
  { y: -7000, t: '前7000' },
  { y: -2600, t: '前2600', era: true }, // era 为真时用转折色标出
];
```

`t` 是显示文本，自己写「前 7000」还是「-7000」都行，但同一演示里要统一。

### terms

演示的界面用词。缺省是兼并题材的说法，换题材时改这里，不要改 `app.js`。

```js
terms: {
  list: '文化分布', // 侧栏「势力版图」的标题
  banner: '文化更替', // 中央字幕上方的小字
  verb: '代', // 字幕里的动词，缺省「灭」
  card: '层位档案', // 右下角卡片的标题
  victim: '被替', // 卡片里「被灭」那一行
  gainer: '归入',
  share: '分布占比', // 缺省「天下占比」
}
```

不是所有题材都在讲谁灭了谁。史前文化、语言分布、宗教传播这类题目，缺省词汇会直接把结论说错。

## STEPS — 关系视图的进程

`view: 'kin'` 的演示用 `STEPS` 定义「演化进程」：一条按顺序走的旁白，每一步停在一个节点上。

```js
const STEPS = [
  { focus: 'person-huangdi', text: '传说里的第一个共主。' },
  { focus: 'person-zhuanxu', text: '黄帝之孙，孙继祖位。' },
];
```

| 字段    | 必填 | 说明                                     |
| ------- | ---- | ---------------------------------------- |
| `focus` | 是   | 停在哪个人物上，必须是 `corpus/` 里的 ID |
| `text`  | 是   | 这一步的旁白                             |

顺序即播放顺序。校验脚本会确认每个 `focus` 都指向真实存在的实体。

## S — 势力

键是势力标识，在整个演示内唯一。

```js
const S = {
  qin: { n: '秦', c: '#c0392b', cap: 'guanzhong' },
  yangshao: { n: '仰韶', c: '#c0392b', cap: 'yiluo', sym: '鱼蛙纹' },
  none: { n: '无主', c: '#3b4757', cap: null },
};
```

| 字段  | 必填 | 说明                                        |
| ----- | ---- | ------------------------------------------- |
| `n`   | 是   | 显示名称                                    |
| `c`   | 是   | 填充色，十六进制                            |
| `cap` | 否   | 中心区域（都城或命名地）的键，`null` 表示无 |
| `sym` | 否   | 标志物，用于图例与悬停卡片                  |

`cap` 决定国名或文化名标在哪一块地上：优先标在 `cap` 指定的区域，若该区尚未归它所有，退而标在它当前最大的辖区。所以 `cap` 应指向该势力或该文化的政治、命名中心，而不是任意一块领地。

史前文化没有都城，`cap` 填命名遗址所在区域即可（仰韶填伊洛，良渚填江东）。

`sym` 是给读者看的实物凭据：仰韶的鱼蛙纹、红山的玉龙、良渚的玉琮。有这个字段时，图例与悬停卡片会把名字和标志物一起显示；没有就只显示名字。

约定用 `none` 表示无主地带。它不是国家，不会出现在灭国判定里，但需要出现在 `S` 中，因为 `INIT` 与 `EVENTS` 会引用它。

## REGIONS — 区域

地图由若干多边形拼成。相邻区域应共用顶点坐标，否则视觉上会出现缝隙或重叠。

```js
const REGIONS = [
  {
    k: 'guanzhong',
    n: '关中',
    p: [
      [107.6, 35.0],
      [107.9, 36.9],
      [110.4, 36.7],
      [111.2, 34.6],
      [110.0, 33.8],
      [107.9, 33.6],
      [106.4, 34.0],
      [105.6, 34.5],
    ],
  },
];
```

| 字段 | 必填 | 说明                                         |
| ---- | ---- | -------------------------------------------- |
| `k`  | 是   | 区域键，全演示唯一                           |
| `n`  | 是   | 显示名称                                     |
| `p`  | 是   | 顶点数组，每项为 `[经度, 纬度]`，至少 3 个点 |

顶点不必首尾重复，渲染时会自动闭合；手动重复会触发校验提示。顶点顺序应保持一致（顺时针或逆时针统一），否则描边与填充在部分浏览器下表现异常。

区域粒度决定了这个演示能表达什么。粒度太粗，看不出蚕食的层次；太细，维护成本会压过来。经验上，一个演示控制在 20 到 60 个区域比较合适。

## INIT — 初始归属

`from` 那一年的归属快照。每个区域都必须有一项。

```js
const INIT = {
  guanzhong: 'zhou',
  longxi: 'qin',
  shangjun: 'none',
};
```

这里不写默认值，缺项会被校验脚本报错。宁可显式写 `none`，也不要依赖隐式回退。

## EVENTS — 年表

演示的核心。按年份递增排列，每条可选地携带归属变更。

```js
const EVENTS = [
  { y: -770, t: 'era', s: '周平王东迁洛邑，秦襄公护送有功，受封诸侯。' },
  {
    y: -623,
    t: 'merge',
    s: '秦穆公伐戎，益国十二，开地千里。',
    ch: { longxi: 'qin', shangjun: 'qin' },
  },
];
```

| 字段  | 必填 | 说明                                     |
| ----- | ---- | ---------------------------------------- |
| `y`   | 是   | 年份，须在 `META.from` 到 `META.to` 之间 |
| `s`   | 是   | 事件描述                                 |
| `t`   | 否   | 类型，见下                               |
| `ch`  | 否   | 归属变更，键为区域，值为新归属           |
| `src` | 否   | 证据性质，见下                           |

`t` 的取值影响侧栏与地图的表现。

| 值       | 含义                                       |
| -------- | ------------------------------------------ |
| `normal` | 普通事件，只记文字                         |
| `shift`  | 范围推移，触发推进动画与档案卡片，不称灭国 |
| `merge`  | 兼并，触发灭国动画、档案卡片与归属变更     |
| `era`    | 时代转折，在时间轴上加重标注               |

`shift` 与 `merge` 的画法相同，区别只有一个：前者不改写「谁灭了谁」的叙述。文化替代、语言扩散、教派传入都属于这一类——地盘换了主人，但说「龙山灭仰韶」是错的。哪一条事件带 `ch`，就以哪一条的 `t` 决定用词。

`era` 也可以带 `ch`。大范围的转折常常一条事件改十几个区域，这时它同时是转折点与变更记录，不必拆成两条。

`src` 标注这条事件的证据性质。这一栏不是装饰：把传说当考古读，是这个项目最该避免的错误。

| 值       | 含义                             | 侧栏标签 |
| -------- | -------------------------------- | -------- |
| `arch`   | 遗址、器物、测年等考古证据       | 考古     |
| `legend` | 神话与后世追述，无当时文字佐证   | 传说     |
| `text`   | 成文文献，有明确出处但未必是实录 | 文献     |

不写 `src` 时不显示标签，适用于证据性质不言自明的题材。

`ch` 允许一条事件同时变更多个区域，这正是「一国被多国瓜分」的表达方式：把几个区域分别指向不同的新归属即可。

同一区域在同一年只能有一个归属。若需要表达「某年某地先从 A 归 B、再归 C」，请拆成两个年份不同的事件，或选一个更细的时间点。

## BATTLES — 战役

```js
const BATTLES = [{ y: -260, n: '长平', lon: 112.9, lat: 35.8, kind: 'battle' }];
```

| 字段          | 必填 | 说明                                             |
| ------------- | ---- | ------------------------------------------------ |
| `y`           | 是   | 年份                                             |
| `n`           | 是   | 名称                                             |
| `lon` / `lat` | 是   | 经纬度                                           |
| `kind`        | 否   | `battle`（兵锋）或 `site`（遗址），缺省 `battle` |

战役点位独立于区域，不受归属变化影响，适合标注那些「发生在某地、但该地归属未变」的战事。

`kind: 'site'` 是给考古遗址留的口子。战场画剑，遗址画空心方点：同一张图上，传说与发掘出来的东西必须能一眼分开。

## RIVERS — 河流

一组折线，每项是 `[经度, 纬度]` 数组，至少两个点。

```js
const RIVERS = [
  [
    [102.6, 36.0],
    [104.0, 36.5],
    [105.8, 37.5],
  ],
];
```

只作地理参照，不参与归属计算。

## ERAS — 阶段

用于侧栏的时期标签与时间轴的分段着色。

```js
const ERAS = [{ from: -770, to: -403, name: '春秋', note: '王室衰微，霸主迭兴。' }];
```

`from` 与 `to` 应连续覆盖 `META.from` 到 `META.to`，不留空隙。首段从 `META.from` 起、末段到 `META.to` 止，中间不留缝也不重叠——校验脚本会检查这三件事。

## NOTES — 年份补注

键是年份字符串，显示在该年的侧栏说明里。

```js
const NOTES = {
  '-403': '三家分晋，田氏代齐，战国序幕拉开。',
};
```

注意键要用字符串形式并带负号，`Number(key)` 能正确解析。

## 语料层：人物与关系

人物、群体、地点、文献以及它们之间的关系不写在 `data.js` 里，而在 `corpus/` 下。理由很简单：同一个人会出现在好几卷里，复制几份必然不同步。

- 字段与词表：`corpus/schema.js`，那是最权威的一份，不要另抄。
- 标识规则：`<kind>-<slug>`，如 `person-huangdi`，全库唯一，发布后不再改。
- 关系方向：从「上位 / 主动」指向「下位 / 被动」，亲子只写「亲 → 子」，子女与兄弟由视图反推。

目前两卷的 `data.js` 还没有引用语料，事件与人物是分开的两套。把两者接起来（事件里的 `refs`）排在 P1，形态见 [docs/design/0003](design/0003-full-history-architecture.md)。在校验脚本支持之前，不要先在数据里写这个字段。

## 新增演示的检查清单

- 目录名与 `META.id` 一致
- 五个文件齐备：`index.html`、`data.js`、`app.js`、`style.css`、`README.md`
- `INIT` 覆盖了所有区域
- 年表按年份递增，且都在 `META` 区间内
- `ERAS` 首尾对齐 `META`，中间不留缝、不重叠
- `t` 只用 `normal` / `shift` / `merge` / `era`，`src` 只用 `arch` / `legend` / `text`
- `app.js` 从 `META` 读取起止年份，不硬编码；滑块的 `min` / `max` 也由脚本设置
- 在根目录 `index.html` 的卡片列表里登记
- 运行 `node scripts/check.mjs` 通过
