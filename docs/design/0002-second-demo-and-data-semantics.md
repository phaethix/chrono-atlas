# 0002 第二个演示：把语义从渲染层搬回数据层

- 状态：已采纳（其中第二演示已于 0004 撤回）
- 日期：2026-10-25

## 背景

[0001](0001-repository-architecture.md) 定下「每个演示独立，不设 `shared/`，等第二个演示写完再回头评估」。第二个演示是《祖先》，前 7000 年至前 1900 年，取自《易中天中华史》第一卷。

这个题材与春秋战国不是同一种东西：

- 时间跨度 5100 年，是前者的九倍多。
- 没有国家，没有疆域，涂在图上的是考古学文化区。
- 没有灭国。「仰韶被龙山取代」不能说成「龙山灭仰韶」。
- 一半事件是神话传说，没有年份，也没有考古证据。

如果第二个演示只能靠改 `app.js` 才能成立，那说明 0001 的「演示自包含」是对的，但「数据与渲染分离」只做到了坐标层面，没做到语义层面。

## 观察：什么真的重复了

逐项对照两份 `app.js`：

| 部分           | 是否重复 | 说明                                                 |
| -------------- | -------- | ---------------------------------------------------- |
| 投影与坐标换算 | 完全重复 | 两组常数、一个 `px()`、一个 `smoothPath()`，逐字相同 |
| 区域绘制与填充 | 完全重复 | 同一套 `REGIONS` 循环                                |
| 状态推导       | 完全重复 | `ownerAt()` 逐事件叠加 `ch`                          |
| 时间轴与播放   | 结构重复 | 但速率、刻度、停顿规则必须可变                       |
| 推进潮动画     | 算法重复 | 形状一样，语义不同：兼并 vs 文化更替                 |
| 字幕与档案卡片 | 结构重复 | 版式一样，用词不同：灭 / 代                          |

重复的是「形状」，不是「意思」。这是关键区别。

## 决定

**不抽 `shared/`**，改为把差异下推到数据层。具体四项：

1. `META.rate`：播放速率。550 年的演示用 3.4 年/秒刚好，5100 年用同一个速率要播半小时。速率是题材属性，不是渲染参数。
2. `META.ticks`：时间轴刻度。原先 `buildTicks()` 里写死了「前 770 / 前 700 / … / 前 221」七个刻度，换个跨度就得改渲染层，直接违反「改数据只碰 `data.js`」。
3. `META.terms`：界面用语。`兼并档案`、`被灭`、`归入`、`天下占比` 这些词原先硬编码在 `app.js` 里，换到史前题材会把结论说错。
4. `EVENTS[].t` 增加 `shift`，`EVENTS[].src` 增加证据性质。前者区分「地盘换了主人」与「谁灭了谁」，后者区分考古、传说、文献。

### 为什么不抽引擎

三条理由，按重要性排：

1. **两个样本证明不了语义相同。** 抽引擎的前提是知道哪些是共性。现在看到的是六处形状重复、两处语义分叉。把语义做成参数，参数会一路涨到十来个，引擎最后变成一份配置文件加一层解释器——比复制两份更难读。
2. **0001 的性质要保住。** 「删掉 `shared/` 不影响任何单个演示独立打开」这条如果还要成立，引擎就不能持有任何状态，那它能封装的也就只剩投影和 `ownerAt`，省不下多少。
3. **零构建比复用值钱。** 两份 `app.js` 各一千行上下，读得完。真到了读不完的时候，说明该换架构了，而不是该加抽象层。

## 规范改动一览

| 改动                    | 原因                                           | 不改会怎样                                   |
| ----------------------- | ---------------------------------------------- | -------------------------------------------- |
| `META.rate`             | 跨度差九倍，固定速率不可用                     | 播完要半小时，读者直接关掉                   |
| `META.ticks`            | 刻度写死在渲染层，换题材必须改 `app.js`        | 「改数据只碰 `data.js`」的约定破功           |
| `META.terms`            | 界面用语是题材属性                             | 史前文化被写成「仰韶灭大溪」，结论直接是错的 |
| `t:'shift'`             | 有归属变更但无灭国                             | 只能借用 `merge`，等于在数据里撒谎           |
| `t:'era'` 允许带 `ch`   | 大范围转折常一条事件改十几个区                 | 拆成两条，时间轴上出现重复年份               |
| `src`                   | 传说与考古必须能分开读                         | 女娲与仰韶并列，读者无从判断哪条能引用       |
| `S[].sym`               | 标志物是这一卷的论证材料（蛙、蛇、羊、牛、龙） | 只能塞进名称或渲染层，两处都不合适           |
| `BATTLES[].kind='site'` | 遗址与战场要能一眼分开                         | 牛河梁和涿鹿长得一样，等于把考古当传说       |

`S[].cap` 的语义顺带放宽为「中心区域（都城或命名地）」。史前文化没有都城，但每个文化都有命名遗址，`cap` 的作用没变，只是名字不再只指都城。

## 校验脚本补了什么

`scripts/check.mjs` 原先只查数据自洽，不查枚举，也不查阶段衔接。补了五项：

- `t` 与 `src` 的取值必须在枚举内。写错一个 `t` 不会报错，只会静默不触发动画——这是最难靠肉眼发现的一类错误。
- `ERAS` 必须首尾对齐 `META`、中间不留缝不重叠。文档早就这么写，脚本从来没查过。
- `META.rate` 必须为正数；按它播完全程超过十分钟时给提示。
- `META.ticks` 必须递增、落在区间内、有显示文本。
- `BATTLES[].kind` 只能是 `battle` 或 `site`。

另外加了一条提示：事件带 `ch` 却标成 `normal` 时警告。地图照样变色，但时间轴不记刻度、播放不停顿，读者会以为那次变更没发生。春秋战国的 `-284` 年正是这种情况，已改为 `shift`。

## 顺带修掉的三处

这三处都是做第二个演示时才暴露的，与题材无关。

1. **滑块范围写死在 HTML 里。** `docs/data-format.md` 要求 `app.js` 从 `META` 读取起止年份，但 `index.html` 的 `<input type="range" min="-770" max="-221">` 是硬编码的。照文档复制一个新演示，`META` 改了、滑块没改，拖到边界就跳。现在范围由 `app.js` 在初始化时设置。
2. **春秋战国的窄屏样式缺了 `@media` 头。** `style.css` 末尾有一段窄屏规则，前面少了 `@media (max-width: 900px) {`，多出一个孤立的 `}`。浏览器丢弃这个 `}`，于是「窄屏隐藏史实说明」的规则落到了桌面端——档案卡片的说明文字在所有尺寸下都不显示。补上 `@media` 后恢复原意。
3. **底图有六处空洞。** 相邻多边形在三点交汇处各占一条边，中间那块谁也没覆盖。多色疆域图里它像一条国界，换成大面积同色就成了明显的黑洞。补法见 `demos/zuxian/README.md`。

第 2、3 条说明一件事：这类错误靠读代码看不出来，得靠换一个题材去用它。

## 代价

- 两份 `app.js` 会各自漂移。改一处共性问题要改两次，这是 0001 已经认下的账。
- `META.terms` 的键一旦增加，两个演示都要跟。约束是：只加键，不改已有键的含义。
- 第三个演示如果还是「区域 + 归属随时间变化」，那就是第三个样本，应该回头重新评估抽引擎（三次重复才算模式）。如果它是人口曲线或行军路线，说明本项目的形态本来就不止一种，维持现状即可。

## 后续

第三个演示出现时，先回答一个问题：它能不能只靠 `data.js` 成立？

- 能，说明这套数据格式已经够用，该写的是文档而不是代码。
- 不能，且不能的原因与前两个相同，说明该抽引擎了。
- 不能，且原因是形态不同，说明 `demos/` 下本就该允许完全不同的 `app.js`，这也是一种答案。
